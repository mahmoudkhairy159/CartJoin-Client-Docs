## حالة التنفيذ — 17 نوفمبر 2026

تم تنفيذ دخول العميل المركزي في بيئة التطوير: يعمل الحساب نفسه بين المتاجر، وتحفظ العلاقات التلقائية قيود الوصول المحلية، ويبقى `users.tenant_id` إسنادًا ثابتًا لأول تسجيل. لا يحذف إغلاق متجر المصدر حساب العميل. معرفات الدخول فريدة عالميًا، ولا يجري دمج غير آمن للحسابات.

يدير مشغل المتجر الوصول المحلي بدل بيانات الدخول العالمية. تتبع العناوين الافتراضية والإشعارات المتجر النشط. طُبقت ترحيلات MySQL وبيئة المعاينة دون تصفير أو إعادة تعبئة. راجع [دليل العملاء وصوره باللغتين](/ar/features/customers).

أصبح لضبط الأوضاع والباقات ذات الإصدارات والفوترة التجريبية والتفعيل بمساعدة الفريق وواجهة الباقات والتقديم المنفصلة تنفيذ وأدلة اختبار. تستخدم المدفوعات والشحن والرسائل موائمات اختبار حتى توفر بيانات المزودين. نُفذت سياسات الخدمة وقبولها والحالات والرد والاعتراض وسبع قوائم أدلة في الخادم ولوحات المشغلين الثلاث؛ [تابع الدليل باللغتين](/ar/features/marketplace-operations). تبقى سجل الرفض وصلاحيات النشر وربط الشحن بدورة الطلب وموافقات النمو والاكتشاف الاختياري قيد العمل. يبقى النشر الحي منفصلًا. [سجل التنفيذ الهندسي](https://github.com/mahmoudkhairy159/CartJoin-Backend/blob/master/documentation/planning/store-marketplace-implementation.md).

## اتجاه المنتج

يخدم كارت جوين الأنشطة المستقلة عبر **وضع المتجر Store**، والأنشطة التي تستضيف بائعين خارجيين عبر **وضع السوق متعدد البائعين Marketplace**. يستخدم الوضعان أساس تجارة واحداً داخل المستأجر. يستطيع التاجر التوسع إلى السوق دون استبدال المتجر أو فقد تاريخ الشراء.

يمثل `CartJoin-Storefront-Frontend` واجهة متجر المستأجر لعملائه. يعرض هوية المستأجر المحسوم ومحتواه وعروضه المؤهلة فقط. ليس موقع تسويق خدمات كارت جوين أو بوابة بيع اشتراكاته أو دليل منتجاته العالمي.

ستقدم **واجهة كارت جوين منفصلة في مرحلة لاحقة** الخدمات والباقات وانضمام المتاجر، ثم الاكتشاف العام للمتاجر والبائعين والعروض المشاركة. يجب ألا تؤخر هذه الواجهة إطلاق أوضاع المتاجر الأولى.

## القرارات التخطيطية المختارة

| المعرف | القرار | السبب التجاري |
|---|---|---|
| D01 | فصل واجهة متجر المستأجر عن المنصة العالمية المستقبلية | حماية هوية التاجر وملكيته وعزل بياناته |
| D02 | حساب عميل مركزي واحد لجميع المتاجر مع إنشاء العلاقة الداخلية تلقائياً | تقليل تكرار التسجيل دون مشاركة بيانات التجارة الخاصة |
| D08 | إبقاء `tenant_id` للعميل المركزي كمصدر أول تسجيل فقط مع السماح بالقيمة الفارغة للتسجيل العالمي | حفظ إحصاءات الاستحواذ دون تقييد الدخول بين المتاجر |
| D03 | فصل الشراء والفاتورة والدفع والاسترداد لكل مستأجر في البداية | وضوح مسؤولية البائع واستمرار العزل المالي |
| D04 | ترقية مضبوطة من المتجر إلى السوق وخفض يراعي الالتزامات | تمكين النمو دون إتلاف التاريخ |
| D05 | اشتراك للمستأجر مع قدرات مدفوعة اختيارية وفصل مصادر الرسوم | إيراد متوقع وتكلفة مفهومة للتاجر |
| D06 | الاشتراك الاختياري في الاكتشاف العالمي ونشر المعتمد والمؤهل فقط | حماية اختيار التاجر وجودة الكتالوج العام |
| D07 | تنفيذ الهوية المركزية في الأساس وتأجيل الموقع والاكتشاف العالميين | دخول جميع المتاجر دون تسجيل متكرر وتأجيل تجميع التسوق العام |

هذه اتجاهات تصميم مختارة وليست إثباتاً لاكتمال التنفيذ. تتطلب الأسعار والعقود والمزودون والتقديرات الزمنية والأهداف الرقمية المرور ببوابات التحقق في [سجل القرارات](/ar/roadmap/decisions).

## قائمة الأولويات

تمثل P0 متطلبات تجربة تجارية آمنة، وتحسن P1 التفعيل والتحويل أو كفاءة التشغيل، وتخص P2 التوسع اللاحق. لا تلغي الأولوية الاعتماد على مراحل سابقة.

| الأولوية | المسار | الأساس القائم | النتيجة المقترحة |
|---|---|---|---|
| P0 | فرض الوضع واستحقاقات الباقة | إعدادات المتجر والصلاحيات واعتماد البائعين | قرار خادم متسق لكل إجراء ومهمة خلفية |
| P0 | هوية العميل المركزية | نموذج عميل مقيد وتوثيق قائم | حساب واحد لكل المتاجر وعلاقة داخلية تلقائية وترحيل آمن |
| P0 | عزل واجهة المتجر | سياق المستأجر والتجارة والمحتوى المقيد | عزل مثبت للتصفح والشراء والتخزين المؤقت والوسائط والتكاملات |
| P0 | الانضمام والفوترة | تهيئة المتاجر ووحدة اشتراك مخططة | تجهيز موجه ودورة باقة وقيود فوترة قابلة للمعالجة |
| P0 | جاهزية الشراء والتنفيذ | الفواتير والدفع والشحن | رحلة ضيف متحققة عند تفعيلها وتجربة ناقل فعلي وتسوية |
| P1 | محرر المتجر والتحويل | المحتوى وأقسام الرئيسية والتقارير | مسودة ومعاينة ونشر وقياس مراحل الشراء |
| P1 | تشغيل السوق | مساحات البائع والعمولات والتسويات | تفعيل أسرع للبائعين ومؤشرات خدمة وقوائم استثناءات |
| P1 | النمو والموصلات | الإشعارات والويب هوك والكوبونات | استرجاع يراعي الموافقة وتكاملات مراقبة |
| P2 | الموقع والاكتشاف العالميان | أساس عميل مركزي ومؤسسات بائعين عالمية | موقع كارت جوين مستقل للتسويق والانضمام والاكتشاف العام الاختياري |
| P2 | نقاط البيع وB2B والكتالوج المشترك والذكاء المتقدم | الفروع وقوائم الأسعار والكتالوج | حالات عمل مستقلة متحققة وليست التزامات أول إطلاق |

## الأدلة الحالية والفجوات

- يوجد الإعدادان `vendor_marketplace_enabled` و`allow_guest_checkout` بالفعل. لا يثبت وجودهما فرض الوضع بالكامل أو اكتمال رحلة الضيف.
- يصنف `TenantTypeEnum` النشاط، مثل التجزئة والجملة، ولا يمثل وضع المتجر أو السوق.
- نموذج العميل `User` مركزي، وتحافظ علاقات `tenant_customers` وسجلات التجارة على عزل المستأجر. مصدر التسجيل ليس المتجر النشط.
- ينشئ الشراء فاتورة لمستأجر واحد وطلبات خاصة بالبائعين. الشراء من عدة بائعين داخل متجر ليس شراءً بين مستأجرين.
- نُفذت الاشتراكات ذات الإصدارات والفوترة التجريبية في التطوير. يدعم الشحن الأدلة اليدوية وملصقات الناقل التجريبية والتتبع المحمي؛ وتبقى جاهزية الناقل الحي بوابة مستقلة.
- قد تتأخر ملخصات المصدر عن التنفيذ. تتحقق المرحلة صفر من المصدر والرحلات الفعلية قبل اعتبار الفجوة عملاً جديداً.

## مقاييس النجاح

قس الوقت حتى أول منتج منشور وأول طلب مدفوع، وإتمام الشراء، واستثناءات الدفع والشحن، والتزام البائع بالإرسال، واسترداد الاشتراك واستبقاء التاجر. حدد المالك والمقام والفترة وخط الأساس قبل وضع أهداف رقمية. حجم المبيعات وحده لا يثبت ربح التاجر أو إيراد المنصة.
