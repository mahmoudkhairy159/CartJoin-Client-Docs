> **حالة التطوير · ١٨ نوفمبر ٢٠٢٦.** أصبح للدخول المركزي وفحوص وضع التجارة والباقات والفوترة التجريبية وطلبات التجار تنفيذ وأدلة اختبار. توفر واجهة المنصة المنفصلة مقارنة الباقات والتقديم. تبقى بوابات التشغيل والاكتشاف اللاحقة عملًا متابعًا، ولا يعني ذلك نشرًا حيًا. [دليل الفوترة الحالي](/ar/features/subscriptions) · [دليل الانضمام](/ar/features/merchant-onboarding).

> **سجل تخطيط — 17 نوفمبر 2026.** السيناريوهات متطلبات للتنفيذ المستقبلي وليست تقارير اختبارات منفذة.

## سلطة القرار

اعتمد المالك هيكل الصفحات الثماني وفوّض اختيار التوصيات التجارية والمنتجية. وأكد صراحة مركزية حساب العميل بين المتاجر وإبقاء `tenant_id` فيه لإسناد التسجيل الأول فقط.

| المعرف | الاتجاه المختار | الحالة وسبب إعادة المراجعة |
|---|---|---|
| D01 | واجهة المتجر معزولة وواجهة CartJoin العامة منفصلة | شرط المالك؛ لا يتغير غرض الواجهة الحالية |
| D02 | دخول مركزي واحد وعلاقات متاجر داخلية تلقائية | شرط المالك؛ لا تسجيل مكرر لكل متجر |
| D03 | الشراء والمال داخل متجر واحد مبدئيًا | توصية؛ لا يراجع إلا بتصميم مالي وتشغيلي مستقل |
| D04 | ترقيات مضبوطة وتخفيض مجدول يراعي الالتزامات | توصية؛ لا حذف أو إعادة كتابة لتاريخ البائع |
| D05 | اشتراك منصة وقدرات اختيارية مدفوعة دون نسبة افتراضية على كل مبيعات التاجر في الإصدار الأول | توصية؛ اعتماد الجدوى والقبول قبل نشر الأسعار |
| D06 | موافقة صريحة وضوابط أهلية للاكتشاف العام | توصية؛ موافقة التاجر وإزالة النشر إلزاميتان |
| D07 | الهوية المركزية مبكرًا والموقع والاكتشاف العام لاحقًا | ترتيب مؤكد؛ الدخول المركزي لا يعتمد على دليل عام |
| D08 | tenant_id في العميل المركزي لإحصاءات مصدر التسجيل فقط | شرط المالك؛ يوصى بقيمة فارغة للتسجيل العام وتصحيح مدقق وحذف آمن |

## قيم تعتمد قبل الإطلاق التجاري

لا تمنع هذه التفاصيل كتابة الخطة. هي بوابات إطلاق وليست إذنًا باختراع مبالغ أو شروط.

| البند | التوصية أو الإجراء | المسؤول |
|---|---|---|
| أسعار الباقات والعملة والضرائب والحدود | دراسة التكلفة والتجار واعتماد عرض ذي إصدار قبل النشر | المنتج والمالية |
| التجربة واستعادة الاشتراك | تجربة قابلة للضبط 14 يومًا كتوصية؛ اعتماد السماح والإشعارات والمحاولات وشروط الإلغاء والاسترداد | التجاري والتشغيل |
| مسؤول الدفع والفاتورة | فصل اشتراك المنصة وبيع المتجر وعمولة البائع ورسوم الخدمات الاختيارية | المالية ومالك النشاط |
| جاهزية المزود والتنفيذ | اختيار مزودي التجربة والتحقق من العقود والربط والاستثناءات | التشغيل والتكامل |
| الاحتفاظ بإسناد التسجيل | حفظ الإحصاءات المسموحة وتحديد إخفاء أو تفريغ الإسناد للمتاجر المغلقة والحسابات المحذوفة | المنتج ومسؤول الخصوصية |
| العملاء القدامى المكررون | إثبات ملكية واستعادة؛ لا دمج بتطابق النص وحده | الهوية والدعم |
| الأهداف العددية للخدمة | خط أساس ومقام القياس وفترته قبل الالتزام | مسؤول المسار |

## مخاطر الأعمال وضوابطها

| الخطر | الضابط ودليل المراجعة |
|---|---|
| استعلام عميل مركزي يكشف نشاط متاجر أخرى | شروط متجر صريحة للتجارة وصلاحية العلاقة وحقول مسموحة وسيناريوهات رفض |
| استمرار استعمال مصدر التسجيل كملكية | حصر كل مستهلك لـ User.tenant_id وفصل تقارير المصدر عن المتجر النشط ومطابقة الترحيل |
| حذف متجر المصدر يحذف العميل | مراجعة المفاتيح ومهام الحذف وحفظ الحساب والعلاقات الأخرى |
| شخصان مختلفان لهما معرف قديم متطابق | استعادة موثقة وقائمة تعارضات وحفظ ربط المعرفات وسجل التدقيق |
| قيد الوضع أو الباقة يهمل طلبًا مدفوعًا | تقييد مبيعات يحفظ التنفيذ والاسترداد والنزاعات والمطابقة المصرح بها |
| اختلاف الدفع والتهيئة | أحداث موثقة دون تكرار ومطابقة وقائمة دفع دون تفعيل |
| اكتشاف يعرض منتجًا قديمًا أو غير مصرح | موافقة نشر وأهلية وفهرسة مراقبة وتسعير حديث عند الشراء |
| كثرة المزايا ترهق التشغيل | بوابات تجريب ومسؤولون وقوائم استثناءات وقياس تكلفة التفعيل والخدمة |

## سيناريوهات القبول عند التنفيذ

| # | السيناريو | النتيجة المطلوبة |
|---|---|---|
| 1 | تسجيل لدى المتجر 1 ثم الدخول لدى المتجر 2 | الحساب والبيانات نفسها دون تسجيل جديد وعلاقة تلقائية بلا تكرار |
| 2 | شراء العميل نفسه من المتجر 2 | يبقى tenant_id للعميل هو المتجر 1 وتخص السلة والفاتورة والطلبات المتجر 2 |
| 3 | دخول مكرر أو متزامن لمتجر آخر | علاقة واحدة للزوج دون تغيير المصدر |
| 4 | إرسال معرف متجر آخر في التسجيل أو تحديث الملف | يستخرج المصدر من سياق موثوق ولا يعدله التحديث العادي |
| 5 | أول تسجيل عبر الموقع العام مستقبلًا | مصدر متجر فارغ وفق التوصية ولا يغيره الدخول اللاحق للمتاجر |
| 6 | إغلاق أو إزالة المتجر 1 | يبقى الحساب المركزي وتجارة المتجر 2 ويخضع الإسناد لسياسة الاحتفاظ |
| 7 | طلب عميل أو موظف طلبًا خاصًا لمتجر آخر | لا ينكشف السجل ويعيد البحث خارج المتجر 404 |
| 8 | حظر متجر للعميل محليًا | لا يعطل الحساب لدى الجميع؛ التعليق الأمني العام إجراء منفصل مصرح |
| 9 | حسابان قديمان يحملان نص البريد أو الهاتف نفسه | لا دمج صامت للبيانات أو الطلبات أو الأرصدة؛ معالجة تعارض موثقة |
| 10 | انتقال الجلسة إلى نطاق مخصص | تسليم هوية موثق وصلاحية متجر جديدة دون تحويل عشوائي أو تسريب رمز |
| 11 | التحول من متجر إلى سوق | بوابات باقة واعتماد دون تكرار فوترة أو تغيير التاريخ عند الإعادة |
| 12 | تخفيض مع إرجاع أو صرف معلق | يمكن وقف البيع الخارجي الجديد وتنتظر النهاية الالتزامات أو سياسة خدمة معتمدة صراحة |
| 13 | حدث دفع مكرر أو متأخر أو خارج الترتيب | لا تحصيل أو تفعيل مضاعف؛ معالجة موثقة ومطابقة |
| 14 | عمليات متزامنة تصل حد الباقة | تطبيق الحد في الخادم للواجهة والتحميل والمهام دون تجاوز بالتزامن |
| 15 | تأخر الاشتراك | إشعارات وقيود معتمدة مع حفظ خدمة الطلبات السابقة للمصرح لهم |
| 16 | بائع معتمد في المتجر 1 يفتح المتجر 2 | لا وصول دون اعتماد المتجر 2 ومطابقة نطاق البائع والمتجر |
| 17 | إلغاء النشر العام أو تعليق التاجر | إزالة الأهلية ومراقبة إزالة الفهرس وحفظ خصوصية البيانات |
| 18 | فتح سعر اكتشاف قديم | يعيد المتجر المالك التحقق من التوفر والإجمالي والشروط قبل الالتزام بالدفع |
| 19 | شراء من عدة بائعين داخل سوق متجر واحد | فاتورة متجر واحدة وطلبات بائعيها دون خلط مال متاجر مختلفة |
| 20 | طلب إحصاءات الاكتساب | فصل مصدر التسجيل عن مشتريات المتجر وعرض التجميعات والعلاقات المحلية المصرح بها فقط |

## أدلة المنافسين والتموضع

نستخدم المنافسين لفهم الرحلات المهمة لا لادعاء التفوق قبل القياس. أدوات البائع وتشغيل السوق توقعات قائمة؛ راجع [CS-Cart Multi-Vendor](https://www.cs-cart.com/multivendor) و[Mirakl Marketplace Platform](https://www.mirakl.com/products/marketplace-platform/). التهيئة الموجهة للتاجر اهتمام قائم أيضًا؛ راجع [بدء العمل في زد](https://help.zid.sa/en/getting-started).

التموضع المقترح لـ CartJoin هو نمو مضبوط من متجر إلى سوق وحساب عميل قابل لإعادة الاستخدام وبيانات تاجر معزولة وتكلفة تجارية واضحة وتشغيل ثنائي اللغة. تُختبر هذه الاختيارات بزمن التفعيل والتحويل والاحتفاظ وجهد الخدمة، ولا تعني ادعاء غياب هذه القدرات لدى المنافسين.

## سجل المراجعة

راجع خط الأساس إعدادات المتجر وتصنيف النشاط ونموذج العميل الحالي المرتبط بالمتجر وبنية الفاتورة وطلبات البائعين ووحدة الاشتراك المخططة ومحول الشحن اليدوي. يُعتمد تدقيق المصدر والرحلات الفعلية دليلًا في المرحلة 0؛ وجود صفحة أو هيكل وحده لا يثبت الجاهزية.

لا تنفذ الخطة ترحيلًا أو سلوك API أو قدرة لوحة تحكم. تبقى أدلة الاستخدام الحالي منفصلة عن المقترحات. لا تضاف صور لميزات مستقبلية إلا بعد وجودها ومراجعتها.
