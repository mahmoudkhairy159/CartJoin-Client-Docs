## Purchase and operations routes

The user API is under `/api/user/v1`, the tenant API under `/api/tenant/v1` and the admin API under `/api/admin/v1`.

| Surface | Methods and fragments |
|---|---|
| Customer | GET `gift-card-offers`, GET/POST `gift-card-purchases`, GET `gift-card-purchases/{publicId}` |
| Customer Cart | POST `cart/gift-cards` with either `code` or owned `public_id` and optional `requested_amount`. DELETE `cart/gift-cards/{applicationId}`. Cart and shipping quotes include masked applications, applied tender and `external_payment_due`. Checkout accepts `quoted_external_payment_due` to protect the reviewed amount. |
| Tenant purchase | GET/POST `gift-card-offers`, PUT `gift-card-offers/{publicId}`, GET `gift-card-purchases` or `gift-card-purchases/{publicId}`, POST `gift-card-purchases/{publicId}/chargeback-review` |
| Tenant staff | POST `gift-cards/{publicId}/resume`, GET `gift-card-approvals`, POST `gift-card-approvals/{publicId}/{approve-or-reject}`, GET/POST `gift-cards/{publicId}/deliveries` |
| Admin and Tenant | GET/POST `gift-card-reconciliation-runs`, GET `gift-card-reconciliation-runs/{publicId}`, GET `gift-card-reconciliation-cases` or `gift-card-security-cases` and their details by public ID |
| Case mutations | POST `gift-card-reconciliation-cases/{publicId}/{action}` with assign, recheck, verify, resolve or dismiss. POST `gift-card-security-cases/{publicId}/{action}` with assign, acknowledge, investigate, resolve or dismiss. An operator with store permissions can also hold or release a card through the security case. |
| Tenant exports | POST/GET `gift-card-exports`, GET `gift-card-exports/{publicId}` or `gift-card-exports/{publicId}/download` |
