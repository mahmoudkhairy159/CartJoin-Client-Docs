## Feature endpoints

Every ticket download goes through the same authenticated ticket scope. The ticket status and attachment visibility values are shared across surfaces.

| Surface | Path under the surface’s `/api/{surface}/v1` prefix | Purpose |
|---|---|---|
| User | `GET/POST /support-tickets`, `GET /support-tickets/{id}` | Create, list, and view the signed-in customer’s tickets. |
| User | `POST /support-tickets/{id}/messages`, `PATCH /support-tickets/{id}/status`, `POST /support-tickets/{id}/follow-ups` | Reply, update status, or start a linked follow-up. |
| Admin, Tenant | `GET /support-tickets`, `GET/PUT/PATCH /support-tickets/{id}` | Read and update the authorized ticket queue. Admin also has export. |
| Admin, Tenant | `POST /support-tickets/{id}/messages`, `PATCH /support-tickets/{id}/status`, `PATCH /support-tickets/{id}/assignment`, `POST /support-tickets/{id}/escalate` | Reply, add an internal note, assign work, change status, and escalate. |
| User, Admin, Tenant | `GET /support-tickets/{id}/attachments/{attachmentId}` | Download an attachment after access is checked. |
| Admin, Tenant | `/faqs`, `/faq-categories`, `PUT /faqs/reorder` | Manage FAQs and categories, including ordering. |
| Admin, Tenant | `GET /{resource}/{id}/preview`, `PATCH /{resource}/{id}/publication` | Preview both languages and set publication explicitly. |
| User | `GET /faqs`, `GET /faqs/{id}`, `GET /faq-categories`, `PUT /faqs/{id}/helpfulness` | Browse published help and vote on an article. |

### Important fields

Ticket creation takes `subject`, `description`, `priority`, and optional `topic`, `order_id` and `attachments[]`. Retry the same submission with the same `Idempotency-Key`. The response has the ticket ID. State changes use `status`, `version`, and optionally `reason`. FAQ publication uses `is_active` as `0` or `1`. Public FAQ search uses `search` and optional `category_id`.
