## How to use it

In the Tenant Dashboard, open **SEO → Metadata**, select a resource and choose English or Arabic. The preview shows the effective metadata. Leave a field blank to inherit its value, or reset the locale to clear its overrides. Select **Open published page** to verify the storefront URL in that language. The preview shows this link only when the resource has a public page.

Under **SEO → Redirects**, enter the old path and its replacement. Use **301** for a permanent move or **302** for a temporary one. Test the old URL after saving. For a migration, use CSV import preview to review conflicts before applying changes. Disable a rule to pause it or delete it to remove it.

Under **SEO → Settings**, validate custom robots rules before saving, or reset to the defaults. After queuing a sitemap rebuild, check its last successful generation time. The Platform Admin SEO screens are read-only across tenants.

## Restrictions and decisions

Publishing and indexing are separate decisions. A hidden or unpublished resource remains unavailable even when it has metadata. A live page takes precedence over a dashboard redirect. Use a live replacement for an old path. A robots crawl block can prevent search engines from seeing that page's noindex instruction.

## Data flow and outcome

Localized overrides and the resource's defaults determine the metadata for published pages. The storefront uses that data for the HTML head and the sitemap lists eligible canonical URLs. A public request for an old path can use a stored slug alias or an active redirect. Browser caches can retain a permanent redirect after the rule changes.

## When something goes wrong

Check workspace, permission, record state and field errors first. If an action times out, inspect the record and its history before retrying. Escalate with the screen, record identifier and time; omit passwords and payment secrets.
