## How to use it

Use the configuration area appropriate to your dashboard: platform settings and feature flags for authorized platform staff; tenant Settings and Reference data for store operation; vendor Store configuration for the offered reference view. Review dependencies before changing a shared value.

Open **Settings overview** to find the configuration screens your role can access. In a versioned editor, **Show change history** lists the changes by revision and time. Where a previous value can be restored, the editor asks for confirmation. If another operator saves first, review your pending edits before discarding them and loading the latest values.

## Restrictions and decisions

Global geography is not tenant-owned catalog data. A flag or saved setting does not prove all associated business workflows are enabled. Configuration changes can affect later calculations but do not rewrite immutable purchase snapshots.

The platform **Archived feature flags** page shows saved values and their original scope. Valid writes to the old feature-flags API return `410 feature_flag_retired`. March 1, 2027 is the earliest planned retirement of those compatibility routes, subject to a client-reference and usage review. Tenant operators can manage supported customer and seller actions in **Store Settings → Feature policies**. Policy edits require a reason. If the revision has changed, reload and review before saving again.

### Feature releases

1. Choose a registered release, then preview its configured and effective policy for a store. Set an owner and expiry. Explicit exclusions take priority over named pilots and the percentage. A store keeps its percentage assignment as the rollout grows.
2. For a staged rollout, save a draft with ordered start times and submit it. The scheduler applies eligible stages in order. A broad expansion or permanent completion needs a second approver. Review stage progress, overdue work and expiry in the release screen.
3. Pause to hold the current cohort. Resume to continue, or use emergency disable to stop new exposure immediately. An expired or unavailable policy closes new exposure. Existing orders, accepted holds and settlement can continue.
4. Open history and review the complete previous policy before a rollback. Restore writes a new revision. Older entries that recorded only field differences remain available as evidence. Confirm completion at the approved final audience to remove the temporary expiry.
5. After completion, authorized communications staff can queue a bilingual in-app notice for the active owners of selected eligible stores. Review the notice status before retrying.

The buyer flash-sale release applies to storefront visibility, pricing and new reservations. Tenant staff can prepare an eligible draft while publication is outside the release. Each write still checks the acting store and permissions.

**Storefront early access** in the tenant feature-policy screen lets eligible stores opt in or leave. Catalog quick filters require a subscription plan that includes the capability, an enabled store policy, and inclusion in the release. Opting in adds an in-stock shortcut above the shopper’s product grid. The original filter controls remain available.

Platform Settings shows whether an encrypted value is configured or needs replacing. Enter a new value to replace it. Leaving the field blank preserves the stored value. Vendor **Workspace terms** displays only masked payout references.

## Localized setting labels

Configuration display names follow the requested interface language, with an English fallback for missing translations. Platform-managed fields remain read-only where indicated. A visible setting label does not by itself prove that every related storefront workflow is enabled.

## Data flow and outcome

Reference/configuration input → permitted tenant/vendor/customer behavior → new calculation or presentation; historical records remain evidence of prior inputs.

## When something goes wrong

Check workspace, permission, record state and field errors first. If an action times out, inspect the record and its history before retrying. Escalate with the screen, record identifier and time; omit passwords and payment secrets.

For deployment, apply the Settings migrations before enabling the updated PHP workers. Verify the migrated flash-sale audience and review quarantined store IDs. Run the Laravel scheduler and workers for the configured release and notification queues. A release with missing policy data remains closed until its policy is recovered. Roll out the updated Tenant Dashboard with the backend because older policy editors omit the required revision and reason on writes.
