## How to use it

Open the correct sign-in page. Enter the identity and password issued for that surface. After sign-in, review your profile and use the permission-filtered sidebar. Use password recovery on that same surface when needed.

<SystemTour tour="feature-access" compact />

## Restrictions and decisions

A hidden menu is not permission to open its URL. Expired sessions require sign-in again. A missing permission differs from a missing or out-of-scope record; never change a record ID to work around an error.

## Data flow and outcome

Identity → surface authentication → session → permissions → allowed screens. Profile updates affect the signed-in actor, not the tenant or vendor organization.

## When something goes wrong

Check workspace, permission, record state and field errors first. If an action times out, inspect the record and its history before retrying. Escalate with the screen, record identifier and time; omit passwords and payment secrets.

## Keep working across tabs

Supported browsers coordinate session renewal between tabs of the same dashboard. The customer storefront can restore an expired access token while its renewal window remains valid. A new sign-in in another tab is treated as a different session, so an old request is not replayed into that account. Logout or a revoked session still requires sign-in. Older saved sessions may need one fresh sign-in after this update. This does not enable silent login across different store domains: use your same central customer credentials when prompted.
