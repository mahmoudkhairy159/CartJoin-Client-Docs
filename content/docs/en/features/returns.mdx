## How to use it

Open **Account → Returns** and select a purchase. Use the page controls for older orders or start from a seller order on your invoice. Select eligible items and follow the shipping instructions. Store operators approve or reject the request, inspect the received quantities, and record restock and refund decisions separately.

<SystemTour tour="feature-returns" compact />

When the store creates a replacement, track the new order from the return. Vendor staff with order access can open the replacement from the return in the approved store workspace. The replacement has its own shipment history.

## Uncertain carrier pickups

On the tenant return detail, open the saved Bosta pickup. When recovery is
available, an operator with permission to update returns and create shipping
labels can enter the carrier tracking number. The carrier account, pickup
reference and tracking details must match the saved request. Recovery attaches
an existing pickup. If definitive evidence confirms it ended before collection,
staff can arrange a manual return. If the outcome stays uncertain, keep the
pickup in review and avoid arranging a second one.

When Bosta is disabled, the saved pickup evidence is still available to
authorized staff. Use the return workflow to record physical receipt and
inspection and to decide on a refund or exchange.

## Restrictions and decisions

Eligibility uses verified delivered quantities per item and the store’s return window and product policy. If parcels arrive at different times, the dates and quantities can differ between items. Only inspected units in suitable condition that staff select for restock return to inventory.

Return detail shows when a refund is awaiting settlement, partially settled, under review, or settled. A like-for-like replacement, when offered by the store, is a separate action for the original seller and variant. Track the linked replacement from the return detail. Availability depends on replacement stock and store permissions.

## Data flow and outcome

Delivered order → return request → decision → receipt and inspection → independent inventory and refund effects. If a financial action succeeds while restocking fails, reconcile the incident rather than issuing the refund again.

## When something goes wrong

Check workspace, permission, record state and field errors first. If an action times out, inspect the record and its history before retrying. Escalate with the screen, record identifier and time; omit passwords and payment secrets.
