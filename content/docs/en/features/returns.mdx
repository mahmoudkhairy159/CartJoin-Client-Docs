## How to use it

Customers open Account → Returns and select an eligible purchase and items. Follow the provided request and shipping instructions. Operators review, approve or reject, receive and inspect actual returned quantities, then choose allowed restock/refund/exchange actions.

## Restrictions and decisions

Eligibility depends on delivery date, configured return window and non-returnable categories. Refunds use inspected rather than requested quantities. Only suitable-condition items selected for restock return to inventory. A return request is not proof that money was refunded.

## Data flow and outcome

Delivered order → return request → decision → receipt and inspection → independent inventory and refund effects. If a financial action succeeds while restocking fails, reconcile the incident rather than issuing the refund again.

## When something goes wrong

Check workspace, permission, record state and field errors first. If an action times out, inspect the record and its history before retrying. Escalate with the screen, record identifier and time; omit passwords and payment secrets.
